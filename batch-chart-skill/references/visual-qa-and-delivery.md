# Visual QA and delivery

生成全部候选图后执行本流程。验收对象是最终渲染文件和其预定的论文物理尺寸，而不是绘图代码或交互窗口。自动检查是预检，不能代替逐图目视判断。

## 逐图视觉验收

以正常阅读尺寸打开每张最终图，并在缩略图或图集视图中再检查一次整体一致性。至少核对：

- 标题、轴标题、刻度、图例、注释和面板标记清晰可读，字体不存在明显过小或过大的情况；
- 任何文字、标记、误差线、图例或子图之间都不发生遮挡；
- 长标签、密集刻度和高类别数没有形成无法辨认的文字墙；
- 图形元素没有被画布边缘裁切，数学符号、中文、负号和特殊字符正常显示；
- 数据区域和留白比例合理，标题或图例没有挤压核心数据区域；
- 线宽、点大小、透明度和颜色对比适合最终尺寸，灰度或色觉差异下仍尽量可区分；
- 颜色与变量语义匹配：分类、顺序和发散色阶没有混用；发散色阶中点有明确含义；连续颜色映射的色条范围、单位和截断说明完整；
- 检查最终显示的刻度：相邻刻度舍入后须可区分，接近零的标签统一显示精度，色条刻度与实际颜色映射一致。多面板对比时核对共用尺度和单位。
- 热力图、散点矩阵、多面板图等密集图在目标尺寸下仍可读；如果不可读，应放大画布、拆分面板、减少标签或改用更适合的编码；
- JPG没有明显压缩伪影、模糊、错误背景色或分辨率不足。
- 图中的主要证据在渲染后确实比基线、网格和辅助注释更醒目；配色在灰度和常见色觉差异下仍能区分。
- 误差条、置信带或数据范围加入后，标签和括号仍留有间隙；没有用另一种标记重复表达同一差异。
- 误差条、拟合、聚类、阈值线、显著性符号和异常点标签都有实际计算或输入依据；没有为了“完整”自动补造统计元素。
- 中文、英文、希腊字母、数学上下标、负号和单位字形均正确，字体替代没有破坏层级或导致溢出。

不要只依赖自动布局。可使用边界框、重叠检测、像素尺寸和缺字警告进行自动预检，但仍需目视检查实际渲染结果。发现问题后修改绘图参数、重新导出并再次验收，直至通过。

字体大小应根据最终画布和阅读场景成比例设置，不把某个固定字号当作所有图的通用答案。除非用户或期刊另有规范，以正常论文版面显示时无需放大即可阅读为通过标准。最终字形不得低于5 pt；常规论文图可从7–9 pt起步，但密度与目标期刊要求优先。数学上下标需检查导出的实际字形。

## 多面板对齐与碰撞检查

- 对需要并列比较的面板，检查最终绘图区的上下/左右边界、宽高与重复间距；默认以1.5 pt作为对齐容差。刻度标签宽度不同不等于绘图区错位。
- 有意不等宽的主面板、插图、色条或图例轴可以例外，但必须记录原因，不能通过放宽全局容差掩盖问题。
- 使用绘图库的最终布局边界框或导出PDF的文本/路径边界做碰撞预检。文字—文字重叠、文字被数据线穿过、文字越出画布属于阻断问题。
- 热力图单元格文字、柱内标注、图像上的比例尺等可能是有意叠加，必须在最终尺寸逐项确认其对比度和可读性。
- 任何改变文字、字体、图例、注释、误差条、轴范围、面板大小或布局的修改，都要重新渲染并重新验收，不能沿用旧报告。

## 图集一致性检查

把全部最终图制作成仅供验收的联系表或缩略图总览，检查：

- 字体、配色、线宽、图例位置和面板编号是否一致；
- 是否有某张图异常拥挤、过空、过亮、过暗或尺寸比例突兀；
- 是否存在重复图、编号跳号或正文/附录标识错误。
- 数据支持时，图集是否采用了多种互补图型，重点系列是否足够醒目，主辅面板和留白是否支撑阅读顺序。逐图检查鲜明配色在最终尺寸下的文字对比、色觉可辨性和数据密度。
- 多来源的图是否准确注明来源。跨源比较图的单位、口径、尺度、样本和颜色映射是否可比，差异是否清楚披露。

联系表只用于验收；除非它对用户有用，否则不计入10–30张正式图表，也不混入最终JPG文件夹。

## JPG导出

- 每张正式图必须导出为JPG，即使同时保留PDF、SVG或其他源格式。
- 使用稳定且可排序的文件名，例如 `fig01_missingness.jpg`、`fig02_group_counts.jpg`。
- 使用适合打印和屏幕查看的像素尺寸、sRGB颜色和高质量压缩；避免通过反复转码降低质量。
- JPG不支持透明背景，导出前显式设置合适的实色背景，默认使用白色。

## 学术源格式

- 绘图库支持时，同时导出PDF或SVG，保持文字可选择/可编辑；JPG仍是强制交付格式。
- 矢量图中的大量点可以栅格化数据标记，但轴、标签和图例应尽量保持矢量文字。
- 导出后实际打开PDF/SVG检查字体替换、缺字、透明度、裁切和图层异常；不能只检查JPG预览。
- 记录目标栏宽或页面宽度、最终尺寸、导出格式和DPI。位图分辨率应按最终物理尺寸计算，而不是只声明一个DPI数值。
- 指定栏宽时，在保存后核对 PDF/SVG 的实际页面尺寸以及 JPG 的像素尺寸；自动紧裁切可能改变设计尺寸。PDF 核对所用字体是否嵌入，SVG 核对可编辑文字在目标环境中的字体回退和布局。

## 能力感知的展示

检测当前工作台的实际能力，不根据产品名称猜测：

- 若支持原生图像附件、内嵌图集、侧栏或画布预览，展示最终通过验收的图。图较多时优先使用可浏览图集或清晰总览，避免在正文中堆叠大量全尺寸图片。
- 若不支持上述展示方式，只提供可下载交付物和简洁文件清单。
- 无论是否能够直接展示，都必须创建并提供JPG压缩包；直接展示不能替代下载交付。

## 文件夹和压缩包验收

建立一个只含最终交付内容的文件夹，例如：

```text
academic_charts_jpg/
|-- fig01_....jpg
|-- fig02_....jpg
|-- ...
`-- figure_manifest.csv
```

`figure_manifest.csv` 至少记录图号、文件名、图题、输入文件及适用的表或分区、使用变量、图表类型、证据角色、独特信息增益、正文或附录建议、图注和视觉验收状态。跨源图另记录适用的连接、换算、筛选、重叠样本处理和样本量，可引用复现记录。将整个文件夹压缩为ZIP后，核对：

1. JPG数量等于最终图表数量且处于10–30范围；
2. 每个JPG都能解码并具有合理的非零尺寸；
3. 文件名与清单一一对应，没有草稿、重复或临时文件；
4. ZIP可以重新打开并列出全部预期文件。

可运行：

```bash
python scripts/validate_delivery.py academic_charts_jpg --zip academic_charts_jpg.zip --json-out qa_report.json
```

脚本负责数量、清单对应、JPG解码、像素尺寸和ZIP结构检查；字体、遮挡、统计适用性和学术解释仍须目视与人工核对。
